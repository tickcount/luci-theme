# Sidebar & menu

- `header.ut`: near-minimal shell — empty `#sidebar` plus a parser-blocking inline script right after it that replays the sidebar cache (below) before first paint; sidebar chrome + nav are otherwise built client-side in `menu-outline.js`.
- `sidebar-outline.js`: state machine for theme (light/dark/device), sidebar collapse/expand, accordion, and mobile drawer — exposed as `window.OutlineSidebar` after the `outline-sidebar-ready` event fires.
- `menu-outline.js`: builds the sidebar chrome after ChatGPT's sidebar — a 52px icon **rail** (logo/home, one button per top-level section, logout at the foot) beside a 238px **panel** (title row: hostname, the command palette's search icon `#cmdk-trigger` bound by `initPalette`, the collapse toggle; then the nav). It resolves the `admin` branch of `ui.menu.load()` into one `.sidebar-accordion-item[data-section]` group per section; the panel shows **one section at a time** (`.is-shown` on the group and its rail button) — the current page's on load, any other picked from the rail without navigating (`sidebar-outline.js`). Collapsed, only the rail stays: a rail button navigates to its section and hovering it lists the section's pages. `ICON_MAP` maps a LuCI menu node's `name` to `/outline/icons/*.svg`; a section it doesn't know (an app's own top-level node — LuCI's menu schema drops any `icon` key, so the name is all the theme gets) gets a monogram of its title instead, a lucide-style data-SVG `<img>` so the `img.outline-icon` rules still apply; deeper levels render as `#tabmenu`. `syncRoute()` re-marks the active page, rail button and shown section (same longest-link-prefix rule as the header.ut replay), breadcrumb and tabs from `L.env` after a [router](router.md) swap without rebuilding the sidebar; `closeSurfaces()` closes palette/drawer/popover.

## Sidebar cache (anti-flash)

`menu-outline.js` snapshots `#sidebar.innerHTML` + scroll position into `sessionStorage['outline.sidebar.cache']` (`{v, lang, html, scroll}`) after render and on `pagehide`. The `header.ut` inline script replays it pre-paint on the next navigation, recomputes the active highlight for the current URL (longest link-path prefix — keep in sync with menu-outline's dispatchpath matching), restores accordion/scroll state, and sets `data-outline-built` / `data-outline-restored` on `#sidebar`.

When restored, `renderSidebarChrome` only re-syncs the hostname, and `renderSidebarNav` preserves accordion/scroll across its authoritative rebuild.

Restored HTML loses inline JS handlers (`innerHTML` serialization), so anything that must work before the re-render needs a delegated listener — e.g. the logout click in `header.ut`, which clears the cache and sets `window.outlineSuppressSidebarCache` so the `pagehide` re-cache stays suppressed.

**Bump `v` whenever the sidebar markup changes shape** (now 6: monogram icons for unmapped sections).

## Navbar layout

Appearance › Navigation › Navbar — the default; only an explicit `sidebar` opts out — sets `html[data-nav="navbar"]` (header.ut, from `outline.appearance.navigation`). It is the same markup laid out by the `Navbar layout` block at the end of `_layout.css`, desktop only: the rail home becomes a brand pill (logo + hostname label), the rail nav a centred section pill (icon + label), the panel is dropped (`display: contents`, nav hidden) except the ⌘K button, which joins logout and the top bar's indicators/theme switch as pills on the right. A section's pages drop under its pill on hover or click — `sidebar-outline.js` reuses the collapsed rail's popover (`_pops()` / `_navbar()`). A navbar has no collapsed state: header.ut's pre-paint script and `sidebar-outline.js` (which now reads `html[data-sidebar-collapsed]`) both treat it as expanded. Phones keep the drawer.

The side pills line up with the content column's edges (`--nav-edge`). When the row is wider than the column, the edge gives way: `sidebar-outline.js` keeps `--nav-reserve` (half the section pill + the wider side group + an 8px gap) up to date with a `ResizeObserver`, and `--nav-edge` takes the smaller of the column edge and `50% - --nav-reserve`, down to 12px.

The theme captures no view transitions (`components/_view-transitions.css` sets `:root { view-transition-name: none }`); swapped and freshly loaded content fades in instead. On desktop, collapsing eases the rail's width (`_layout.css`) and `#main-wrapper`, a flex-1 sibling, follows it frame by frame: the content is pushed, never snapped and slid back. `sidebar-outline.js` sets `html[data-sidebar-anim]` on the first toggle so a page load never plays the transition.
